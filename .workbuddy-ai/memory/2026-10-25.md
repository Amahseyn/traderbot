## Research pages code-level debug (no browser)

Fixed 6 bugs across the Research pages (Overview, /new Discovery, /custom Pipeline) from static code
analysis:

1. **`app/new/page.tsx` — `onSelectHistory` set jobId when hiding a run.** When a user clicked
   "Hide" on a discovery history run, `onSelectRun(null, row.job_id)` still passed a truthy
   `historyJobId`, so `setJobId(historyJobId)` fired — the JobMonitor and DiscoveryJobResults
   jumped to the run the user was trying to dismiss. Fix: only update `jobId` when `runId` is
   truthy (i.e., selecting, not hiding).
2. **`app/page.tsx` — overview stat-card links were wrong.** "Compare sessions" linked to `/data`
   (data export) instead of `/experiments#compares`; "Parameter sweeps" linked to `/custom`
   (research pipeline) instead of `/experiments#sweeps`. Fixed both hrefs.
3. **`OpportunityDiscoveryPanel.tsx` — 4 raw `<select>` elements.** Data source, exchange, trend
   sort, and trend direction used ad-hoc `<select className="rounded-lg ...">` with inconsistent
   styling (no focus ring, no inner shadow, wrong radius). Replaced all with the `SelectInput`
   component from `@/components/ui/Field` for design-system compliance.
4. **`JobForms.tsx` — `text-white` on `bg-accent` (2.8:1 contrast).** The "Go to Data" link in
   `EmptyDatasets` used raw `text-white` on the accent background — explicitly forbidden by
   MASTER.md (white on `#5B9AFF` fails AA). Replaced with the `Button` component which uses
   `text-on-accent`. Also removed the raw `hover:bg-blue-500`.
5. **`DiscoveryJobResults.tsx` — empty state when job completes with no report.** When a
   discovery job completed but produced no report and no query error (e.g., no artifact path in
   log + no DB run), the card body was silently empty. Added a fallback message.
6. **`app/custom/page.tsx` — `rounded-xl` on run-blockers alert.** Design system uses
   `rounded-lg` for cards/containers; `rounded-xl` is not in the token system. Fixed.

`tsc --noEmit` clean after all changes. All three pages return 200.

## Backtesting optimizer audit review

Reviewed a 7-point external audit against actual code in `traderbot/backtesting/`,
`traderbot/algorithms/optimized_params.py`, and `lab/`. Verdict per item:

1. **Optuna dynamic categorical search space (CONFIRMED — real bug).**
   `tune_search_space.py:119-123` filters `slow` choices per-trial based on the
   sampled `fast`, then calls `trial.suggest_categorical("slow", slow_choices)`.
   Optuna requires invariant choice sets across trials; this raises
   `CategoricalDistribution` error on any trial whose `fast` differs from trial 0.
   The `except` in `optuna_tune.py:183-187` converts it to `TrialPruned`. Same
   pattern for `trend_slow_period` (lines 125-132). Fix: sample from the full grid
   and reject `fast >= slow` via `raise TrialPruned` or a post-hoc constraint.

2. **Holdout test evaluation on full bars (CONFIRMED — data leakage).**
   `optuna_tune.py:235` evaluates `test_bars if use_validation_split else bars`.
   When `use_validation_split=False` with `holdout_tail_bars` set, `train_bars` is
   `bars[:-holdout]` but the final test runs on the full `bars` (includes training
   data the optimizer fit on). Should be `test_bars` unconditionally when a holdout
   exists.

3. **Walk-forward warmup position leakage (PARTIALLY CONFIRMED — equity leakage
   real, trade stats mitigated).** `walk_forward.py:93` constructs
   `test = bars[test_start - warmup : ...]`. `_oos_segment` (line 65-75) filters
   trades to `t.timestamp > start_ts`, so round-trip trade stats exclude warmup
   opens. BUT segment return uses `start_equity = curve[warmup-1][1]` to
   `curve[-1][1]` — if a position opened in warmup, its unrealized PnL is baked
   into `start_equity` and the equity-curve return reflects in-sample decisions.
   Under `execution="next_open"` (broker.py:267-271), a signal on the last warmup
   bar fills at `test[warmup]` open with `ts > start_ts`, so it counts as OOS.
   Trade-level leakage is mitigated; equity-curve return leakage is not.

4. **apply_sweep_winner ignores timestamps (CONFIRMED — temporal leakage risk).**
   `optimized_params.py:122-128` queries
   `SELECT best_params_json ... ORDER BY created_at_utc DESC LIMIT 1` with no
   `optimize_end_utc` filter. `resolve_optimized_namespace` (line 239-250) applies
   these params unconditionally. `compare_session.py:139-149` does the same.
   No comparison against `run_start_unix_seconds`. A sweep trained on overlapping
   or full-dataset data will be applied to the evaluation window silently.

5. **Optuna objective rewards ineligible candidates (CONFIRMED — distortion).**
   `optuna_tune.py:201-203` returns `float(row["validation_return_pct"])`
   regardless of `eligible`. Compare `run_strategy_optuna_in_sample` (line 356-357)
   which returns `float("-inf")` when not eligible. The tune variant sets
   `trial.set_user_attr("eligible", ...)` but the TPE objective value ignores it,
   so 1-trade lucky candidates can dominate exploration.

6. **optimize_end_utc overwrites test window (CONFIRMED — metadata misreporting).**
   `optimize_select.py:130-134` calls `fit_window_utc_from_bars(bar_list, ...,
   holdout_tail_bars=None)` on 100% of bars. In validation mode, training used
   only the first 60% (`split_chronological`), but the stored `optimize_end_utc`
   is the last bar's close. `fit_window_utc_from_bars` does support
   `holdout_tail_bars`, so the fix is to pass the held-out count.

7. **No indicator warmup on validation/test slices (CONFIRMED — cold-start bias).**
   `validation.py:69-73` and `optuna_tune.py:156-160` use `split_chronological`
   (disjoint slices). Algorithms are re-instantiated fresh on validation_bars and
   test_bars with no warmup prefix. Strategies needing N bars of lookback
   (ma_trend ~200, macd_cross ~45) are blind for the first N bars of each slice.
   Walk-forward avoids this via its `warmup_bars` prefix; validation/optuna do not.

**Net:** 6 of 7 are accurate as written; item 3 is accurate for equity-curve
return but the trade-statistics mitigation in `_oos_segment` was understated by
the audit. Items 1, 2, 5 are the highest priority (search-space correctness,
test-set purity, objective validity).

## 1m trading diagnostic → cost-aware edge gate (strategies)

**Diagnostic confirmed** on `data/ARBUSDT_1.csv` / `data/FILUSDT_1.csv` with Hyperliquid taker
costs (0.045% fee + 0.05% slippage per leg = 0.190% roundtrip): zero-cost reruns showed
`macd_cross` ARB at **-0.19% gross vs -33.79% net** (216 roundtrips, 11-min median hold) — 99% of
the loss was friction. All five threshold strategies ran with `context_bars=0`,
`price_confirm=False`, i.e. blind thresholds.

**Fix shipped**
- `price_context.py`: `required_signal_edge_pct`, `signal_clears_cost` (magnitude, mean
  reversion), `trend_signal_clears_cost` (signed, trend), `trend_edge_window_bars`,
  `recent_return_gate` (extracted from `apply_mean_reversion_context` so trend can reuse it).
- New knobs on `sma_cross`/`ema_cross`/`rsi_threshold`/`macd_cross`/`bollinger_mean_reversion`:
  `min_edge_over_cost` (None → auto), `roundtrip_cost_pct` (None → venue), `entry_order_mode`
  (`market`|`maker`) + `entry_offset_pct`/`entry_ttl_bars`.
- `strategy_defaults.apply_high_frequency_edge_default` resolves the gate to **1.0 on ≤5m bars,
  0 above**; `apply_venue_cost_default` resolves the roundtrip from the CSV venue.
- `entry_orders.py::MakerEntry` — post-only limit entries only (`entry_side="buy"`); exits stay
  market. `uses_order_engine` is True only in maker mode.
- `trading_costs.roundtrip_cost_rate/pct` (+ `maker_entry=True` → 0.11% on HL, 0.70% on Nobitex).
- Registry: new kwargs wired into `_KWARGS_FROM_ARGS`; `min_edge_over_cost` /
  `roundtrip_cost_pct` / `entry_order_mode` excluded from `strategy_param_names` (tuning would
  propose nonsense), `entry_offset_pct`/`entry_ttl_bars` excluded for the five threshold
  strategies only (scalp_dip keeps them).

**Measured (market entries, default multiple)** — ARB: macd -33.79→-3.25%, sma -29.16→-12.35%,
ema -22.05→-3.53%, bollinger -6.16→-6.02%. FIL: macd -19.94→-2.79%, sma -14.48→-1.96%.
Coarse bars untouched (60m macd on ARB was -1.84% with the gate off; **-22.30% if forced on** —
that measurement is why the gate is resolution-gated rather than global).

**Key learning:** a signed-momentum gate is right for `sma/ema/macd` on 1m–5m but wrong on 60m
(MACD cross-ups are reversal signals that follow a decline, so demanding trailing momentum
filters the good entries). Magnitude-only was much worse on 1m (`macd` ARB -20.31% vs -3.25%).

**Test environment gotcha:** the sandbox safe-delete bulk guard (>50 deletes/turn) aborts full
`pytest tests/` runs at teardown, and a stale `$TMPDIR/pytest-of-unknown` makes every test error
with `PermissionError: EEXIST`. Reliable recipe: one **fresh** `TMPDIR=$(mktemp -d /tmp/...)` per
run (never reuse), or run file-by-file. `--basetemp` makes the guard worse.
**Final end-to-end check:** reran the before/after comparison through the real path
(`namespace_for_strategy_backtest` → `strategy_kwargs_from_namespace` → `algorithm_for_id`)
instead of hand-passed kwargs, and the numbers reproduce exactly (ARB macd -33.79→-3.25%,
432→53 fills; FIL macd -19.94→-2.79%, 183→17). Resolution gating confirmed on real files:
`ARBUSDT_1`/`AAVEUSDT_5` → multiple 1.0; `ADAIRT_15`/`ARBUSDT_60` → 0.0. Venue cost resolves
`0.0019` (HL) vs `0.009` (Nobitex IRT). 14 strategy-adjacent test files → 125 passed.
