# 2026-10-24

## Fixed: "Maximum update depth exceeded" on /optimizer (Lab UI)

- Symptom: `OptimizerDatasetSection.tsx:142` — setState in `useEffect` looping with
  `StrategySweepForm.tsx:173`.
- Root cause: two effects owned the same `sweepDatasetId` state with contradictory
  invariants. The section resolved an empty filter result to `""` and wrote it up;
  the form's "default to first dataset" effect then refilled it → infinite ping-pong.
  Trigger: any filter (market click, search, interval) that matches zero catalog files.
- Fix:
  - `lib/optimizerCatalog.ts`: new `nextSingleDatasetId(filtered, currentId)` returns
    `string | null`; `null` = "no change", explicitly covering the empty-filter case.
  - `OptimizerDatasetSection`: single owner of the narrowing; effect depends on the
    resolved primitive id (not the `filtered` array) and calls the parent through a
    ref so an inline callback identity can't re-trigger it. `selectMarket` no longer
    writes the id (only sets the symbol filter).
  - A selection hidden by filters is kept visible in the select, labelled
    "(hidden by filters)", instead of rendering blank.
- Tests: 4 new cases in `src/lib/optimizerCatalog.test.ts` (58 UI tests pass).
- Note: managed node 22.22.2 is x64 under Rosetta and breaks vitest
  (`@rollup/rollup-darwin-x64` missing). Run UI tests with `/opt/homebrew/bin/node`.
